# Feature Specification: Full HugBor adoption (new taxonomy)

**Feature Branch**: `005-style-robustness`

**Created**: 2026-10-06

**Status**: Draft (supersedes the earlier hybrid draft of the same branch)

**Input**: User description: "Adopt the HugBor ServiceNow dataset fully: its 15-category taxonomy replaces our 8, its labeled incidents replace our previous training set (the owner trusts the dataset's labels more than his own hand corrections). Thin categories get topped up by the local model. Goal: a stronger, style-robust classifier on the new taxonomy, measured against a stratified held-out test set — zero cloud API traffic."

## Background (diagnosis)

- The current model is excellent on short, templated synthetic texts (98–99%
  on its frozen test), but errs on longer, natural incidents (4/8 probe) —
  style sensitivity.
- **HugBor/servicenow_incidents_slm6** (1,640 rows, 15 balanced categories)
  offers realistic, internally consistent incidents (title/body/category/
  resolution align) with ServiceNow fields — a stronger base than our
  previous pipeline's data.
- The owner explicitly does NOT trust the earlier hand corrections (T017,
  T031) as much as the dataset labels: the HugBor labels are therefore the
  reference, and the previous mindweave-derived training set (997 rows) and
  the old frozen test sets (v1/v2, 8-category) are **archived, not used** in
  this feature.
- HugBor taxonomy (15 categories, rows): Network 209, Application 174,
  Database 145, Security 134, Hardware 119, Performance 118,
  Printer/Peripherals 109, VPN 101, Email 100, Backup/Recovery 96,
  Access Management 80, Cloud Services 68, Data Center 68, Software 66,
  Telephony 53. Thin categories (<100) get topped up by the local Qwen.
- **Taxonomy amendment (2026-10-06, owner-approved):** the label-trust
  spot-check measured 85.3% (< 90% threshold) and the analysis showed the
  disagreements are not noise but overlapping neighbor categories — above
  all Software ↔ Application (the dataset's own rule "client software =
  Software, business app = Application" is ambiguous even for humans).
  Therefore **Software is merged INTO Application** (14 categories from now
  on). The remaining borderline pairs (Application ↔ Cloud Services,
  Application ↔ Performance, Telephony ↔ Network, Data Center ↔ Hardware)
  are kept as-is and documented: weaker per-category numbers are accepted
  there. After the merge the re-measured agreement is 88.6%; the owner
  approved the 85% threshold with the documented carve-out (SC-001).
- **Thin-category update after the merge:** <100 train rows now also
  includes Backup/Recovery (77), VPN (81), Printer/Peripherals (87),
  Performance (94) and Access Management (64) — the top-up (US2) covers all
  of these to reach ≥100 train rows/category (SC-003).
- Texts are longer (median 532 chars) than the recipe window (128 tokens) —
  truncation is documented (FR-004), the recipe stays unchanged.
- Label trust is still verified cheaply (see US2): a local-model spot-check,
  not hand corrections.
- The 8 hand-written probe incidents (2026-10-06) are remapped to the new
  taxonomy (all 8 map cleanly: Access Management, Hardware, Network, Email,
  Application, Printer/Peripherals, Security, Telephony) and kept as the
  wild probe set.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - HugBor tidy, split, and label-trust spot-check (Priority: P1)

The owner wants the HugBor dataset in the project's tidy format with a
stratified, fixed-seed train/test split — and a cheap, local, numeric
verification that the labels are trustworthy before any training.

**Why this priority**: Everything stands on the labels; the mindweave lesson
(noise at 12%) demands a measured trust check, but the owner declines hand
corrections — so the check is a local-model agreement measurement.

**Independent Test**: the tidy table exists with the documented schema; the
split proves 0 overlap; the spot-check report shows the local teacher's
agreement rate on a stratified sample (≥ a specified threshold).

**Acceptance Scenarios**:

1. **Given** the HugBor rows, **When** the tidy+split runs, **Then** every
   category keeps a proportional share of test rows, and the overlap checker
   proves 0 overlap (id + normalized text).
2. **Given** a stratified sample (e.g. 5 rows/category), **When** the local
   teacher labels it blind, **Then** the agreement rate with the dataset
   labels is written to a file and reaches the threshold (SC-001).

---

### User Story 2 - Thin categories topped up locally (Priority: P2)

Categories with fewer than 100 rows (Telephony, Software, Cloud Services,
Data Center) get additional examples generated by the local Qwen, in
HugBor's realistic register, with a hand-reviewed sample before entering
training.

**Why this priority**: Balanced categories improve per-category accuracy;
the local model produces them at $0 with zero outbound traffic. The owner's
review of the *generated* rows stays a gate (dataset rows need no review,
generated ones do).

**Acceptance Scenarios**:

1. **Given** the local endpoint, **When** generation runs for the thin
   categories, **Then** each thin category reaches ≥100 train rows after
   merging.
2. **Given** the generated sample, **When** the owner reviews it, **Then**
   rejected rows do not enter the training set.

---

### User Story 3 - New baseline on the new taxonomy (Priority: P1)

A fresh 3-seed baseline on the HugBor training set (unchanged recipe), with
per-category accuracy, on the held-out test set — and the wild probe
remapped to the new taxonomy measured alongside.

**Why this priority**: the taxonomy change breaks comparability with the old
numbers (documented, not hidden); the new baseline is the reference for
every later feature.

**Acceptance Scenarios**:

1. **Given** the training set, **When** 3-seed training runs, **Then** the
   metrics file contains overall and per-category accuracy with mean ± stdev.
2. **Given** the same model, **When** the probe set (remapped) is measured,
   **Then** the probe accuracy is reported next to the old-taxonomy 4/8
   baseline.

### Edge Cases

- The spot-check shows LOW label agreement (the dataset is less trustworthy
  than believed): the run stops and reports; the feature does not train on
  untrusted labels (restart: reconsider hand review or another source).
- Truncation cuts decisive content on long rows: the truncated-row count is
  reported; if high, the report flags it (recipe change stays out of scope).
- Generated top-up rows drift from HugBor's register: the review sample
  filters them; stats show the source mix per category.
- The taxonomy change invalidates old metrics: documented — old numbers stay
  valid only in their own (archived) context.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: A tidy table from HugBor (task, id, text, label, split) with the
  full 15-category taxonomy; the HugBor commit hash recorded (Constitution
  III).
- **FR-002**: Stratified, fixed-seed train/test split per category (test
  ratio documented), 0 overlap verified (id + normalized text).
- **FR-003**: A local-model label-agreement spot-check on a stratified sample
  (≥5 rows/category), with the agreement rate written to a file; threshold
  below → the pipeline stops before training.
- **FR-004**: Uniform, documented truncation to the recipe window (first
  ~500 characters), with the truncated-row count reported; the recipe
  (maxlen=128) itself unchanged.
- **FR-005**: Local-Qwen top-up only for categories with <100 train rows,
  in HugBor's register, versioned, deduplicated, English-only, owner-reviewed
  (MANUAL GATE).
- **FR-006**: Training uses the unchanged recipe; 3 seeds (0, 1, 2); metrics
  (overall + per-category, mean ± stdev) written to a file.
- **FR-007**: The wild probe set is remapped to the new taxonomy and measured
  with the same model; old-taxonomy metrics are archived, not compared as
  gates.
- **FR-008**: Zero cloud LLM traffic: generation and spot-check target only
  127.0.0.1; the HugBor download is a one-off dataset fetch.

### Key Entities

- **HugBor tidy row**: (task, id, text, label, split) — text = short
  description + description, truncated per FR-004.
- **Label-agreement spot-check**: the local teacher's blind labels vs dataset
  labels on a stratified sample; the trust evidence.
- **Top-up rows**: locally generated examples for thin categories,
  owner-reviewed.
- **New frozen test set**: the stratified held-out HugBor rows with dataset
  labels (spot-check-verified); replaces v2 as the reference.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001 (label trust)**: local-teacher agreement with dataset labels
  ≥ 85% on the stratified spot-check sample; below → stop before training.
  **Carve-out (owner-approved 2026-10-06):** disagreement inside the four
  documented borderline pairs (Application ↔ Cloud Services,
  Application ↔ Performance, Telephony ↔ Network, Data Center ↔ Hardware)
  is an inherent taxonomy overlap, not label noise — those pairs are
  expected to cap per-category accuracy at ~60–80%, and are accepted as
  such. (Measured: 88.6% overall; 11/14 categories at 100%.)
- **SC-002 (new baseline)**: overall accuracy on the held-out test set
  ≥ 90% (3-seed mean) — the first-measurement reference for the new
  taxonomy; no comparison gate against old-taxonomy numbers.
- **SC-003 (coverage)**: every category has ≥100 train rows after the top-up
  (thin ones: Telephony, Software, Cloud Services, Data Center), and the
  owner-approved generated sample is ≥90% ok (MANUAL GATE).
- **SC-004 (robustness probe)**: remapped probe accuracy ≥6/8 on at least 2
  of 3 seeds (baseline: 4/8 on the old taxonomy).
- **SC-005**: zero cloud LLM traffic (verifiable: LLM requests target only
  127.0.0.1).

## Assumptions

- The HugBor dataset's license permits this use — verified before training.
- HugBor labels are consistent enough to serve as the reference, subject to
  the SC-001 spot-check.
- The decisive content (symptom + impact) sits in the first ~500 characters
  for the vast majority of rows.
- Old data (mindweave 997 rows, v1/v2 test sets) is archived and unused;
  the old numbers' context is documented in RESULTS.md.

## Out of Scope

- Changing the recipe (maxlen, hyperparameters). *Restart condition: separate
  spec, if truncation proves lossy in measurement.*
- Hand corrections of dataset labels (the owner declined; the spot-check is
  the verification mechanism).
- Remapping the dropped old 8-category data into the new taxonomy.
  *Restart condition: separate spec, if the new baseline shows the extra mass
  is needed.*
- Production ServiceNow integration (unchanged from 001).
